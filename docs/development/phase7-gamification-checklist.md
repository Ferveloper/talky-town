# Phase 7 acceptance checklist

Six increments: pure rules/catalog; atomic live awards; stable completion rewards;
derived progress/contracts; seed and reconciliation; PostgreSQL regression/docs.
Run focused tests after each, then the complete acceptance gate.

- [x] Ledger-authoritative XP; numeric level separate from proficiency.
- [x] Madrid calendar streaks with injected clock, midnight, month/year, leap-day and DST tests.
- [x] Seven idempotent event-based badges; genuine persisted correction criterion.
- [x] Independent idempotent catalog installation, synchronization and preserved awards.
- [x] Atomic free-talk reward after three accepted events; stable replay/end response.
- [x] Guided mission XP unchanged; no duplicate end reward.
- [x] Read-only derived profile/progress with canonical locked/unlocked catalog.
- [x] Dry-run/apply historical reconciliation, explicit linkage limitations and repeatability.
- [x] Seed twice, runtime award then seed, stable counts/provenance/provider/profile tests.
- [x] Concurrency, transaction rollback and deterministic Mock walkthrough coverage.
- [x] No frontend code, schema changes, migrations or real AI inference.

Final commands: `pnpm install --frozen-lockfile`, `pnpm format:check`, `pnpm lint`,
`pnpm typecheck`, `pnpm db:validate`, seed/verify twice, `pnpm test`, `pnpm test:db`,
`pnpm build`, catalog twice, reconciliation preview/apply/repeat and the targeted
Mock walkthrough. See the [implementation report](phase7-implementation-report.md)
for actual outcomes and counts.

Phase 8 remains responsible for frontend integration and deduplicated celebrations.
The Phase 5 manual real-provider gate remains separate and is not satisfied by
offline gamification tests. No commit, push, PR or tag is part of this execution.
